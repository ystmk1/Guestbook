# Sympoiesis

ACT 2026 전시 방명록.

모눈 종이 한 장. 가운데를 흐르는 척추(`0`)에서 좌우로 멀어질수록 숫자가 커지고,
멀수록 칸이 성기게 흩어져 손그림 등고선처럼 보인다.

**방명록 한 줄 = 칸 하나.** 화면 곳곳에 무작위로 한 칸씩 번진다.
채워진 칸에 마우스를 올리면 그 줄이 나온다. 이름은 원하면 쓴다.

본문에는 글자수 제한이 없다. 쪽지는 줄이 늘면 같이 길어지고,
화면 밖으로 나가지 않게 자리를 잡는다 — 오른쪽에 자리가 없으면 칸 왼쪽으로,
아래쪽 칸이면 칸 위로 뒤집어 뜬다. 화면 테두리에서 최소 16px 은 띄운다.

칸 색은 `#696969` ↔ `#C9C9C9` 사이를 6.5초 주기로 천천히 오간다.
회색을 고정해두면 흰 바탕에 묻혀 잘 안 보여서, 숨쉬듯 움직여 시선을 붙잡는다.

칸마다 위상이 다르다. 전부 같은 위상이면 판 전체가 한꺼번에 맥동해서
전시장에서 거슬리고, 흩어놓으면 느린 일렁임이 된다.

숫자는 색을 뒤집지 않고 먹색으로 두되 진하기만 따라간다. 흰색 ↔ 먹색으로
뒤집으면 그 중간에서 바탕과 같은 회색이 되어 글자가 한 번씩 사라진다.

## 실행

```bash
npm install
npm run dev
npm run build
```

기록은 이 브라우저의 `localStorage` 에 저장된다. 인터넷 없이 동작한다.

## 성능

| | gzip |
| --- | --- |
| JS | **4.1 KB** |
| CSS | **1.1 KB** |

외부 런타임 의존성이 없다. 모눈과 안 채워진 칸은 한 번만 그려 오프스크린
캔버스에 캐시해두고, 매 갱신마다 통째로 복사한 뒤 채워진 칸만 그 위에 얹는다.
칸이 수천 개여도 모눈을 다시 그릴 일이 없다. 매 프레임 하는 일은
캐시 복사 한 번과 채워진 칸만큼의 사각형·숫자 그리기뿐이다.

칸이 숨쉬므로 루프는 상시 돌지만 30fps 로 제한한다. 6.5초에 한 번 오가는
느린 변화라 그 이상은 의미가 없고, 하루 종일 켜두는 화면이라 그만큼 덜 먹는다.

## 확대·축소

브라우저 확대(`Ctrl` +/-)는 CSS 픽셀 전체를 키워서, 그대로 두면 제호와
입력줄까지 같이 커진다. 두 겹으로 막는다.

1. **실수로 확대되는 경로를 막는다** — 트랙패드 핀치와 `Ctrl`+휠.
   전시장에서 확대가 되는 건 대개 이쪽이고, 페이지에서 확실히 막을 수 있다.
2. **그래도 확대되면 배율을 재서 되돌린다** — 키보드 단축키는 브라우저가
   페이지보다 먼저 가져가는 경우가 있어 막는 걸 보장할 수 없다.
   `devicePixelRatio` 로 배율을 재서 `--zoom` 에 넣고, 제호·입력줄·알림은
   그 값으로 나눠 물리적 크기를 유지한다.

**모눈은 나누지 않아 그대로 커진다.** 확대하면 칸이 커지고 개수가 줄어든다.

> 처음 열렸을 때를 100% 로 본다. 이미 확대된 채로 열면 그 상태가 기준이 된다.
> 전시장 노트북은 한 화면에 고정이라 문제되지 않는다.

## 전시 마지막 날 — 기록 내려받기

**`Ctrl` + `Alt` + `Shift` + `O`**

두 파일이 함께 받아진다.

| | |
| --- | --- |
| `.txt` | 원문. 긁어서 쓸 수 있다. 도록·아카이브용 |
| `.pdf` | A4 판면 그대로. 표제 · 쪽번호 포함 |

관람객이 우연히 누를 일이 없게 조합을 길게 잡았다.
브라우저가 파일 두 개를 연달아 받는 걸 처음 한 번 물어볼 수 있다 — 허용하면 된다.

### PDF 를 만드는 방식

PDF 에 글자를 "글자로" 넣으려면 한글 폰트를 CID 서브셋으로 임베딩해야 한다.
코드도 무겁고 라이브러리도 커진다. 그래서 페이지를 캔버스에 그려 JPEG 로 만든 뒤
**PDF 에 이미지로 박는다.** 폰트 자원이 아예 필요 없어 외부 의존성이 0 이다.

대신 PDF 안에서는 글자를 긁을 수 없다. `.txt` 를 같이 주는 이유다.

> 캔버스의 `fillText` 는 DOM 과 달리 웹폰트를 알아서 받아오지 않는다.
> 그리기 전에 `document.fonts.load()` 로 필요한 조각을 미리 받는다.
> 안 그러면 아직 안 받은 조각의 글자가 대체 폰트로 나온다.

## 글자

전부 **SM3신중고딕-03** 한 벌이다. 외부 CDN 요청은 없고 전부 자체 호스팅한다.

### 이 폰트의 함정

`SM3신중고딕-03.otf` 는 한글 11,172자가 모두 cmap 에 들어있지만
**그중 8,822자는 charstring 이 `endchar` 뿐인 빈 글리프다.** 실제로 그려지는
것은 KS X 1001 완성형 2,350자뿐이고, GSUB 테이블도 없어서 조합으로 만들어지지도
않는다.

이걸 그냥 `unicode-range` 에 다 넣으면 브라우저는 폰트가 그 글자를 가졌다고
믿고 대체 폰트로 넘어가지 않는다. 그러면 방문자가 `똠`, `쒜`, `뷁` 같은 글자를
쳤을 때 두부(□)도 아니고 **아무것도 안 보인 채 사라진다.**

그래서 [`scripts/build-font.py`](scripts/build-font.py) 는 원본에서 외곽선이
실제로 있는 코드포인트만 골라 범위를 만든다. 빠진 글자는 뒤의 시스템 한글
폰트(맑은 고딕 등)로 자연스럽게 넘어간다.

### 조각내기

| | |
| --- | --- |
| 원본 OTF | 2.04 MB |
| woff2 32조각 합계 | **0.18 MB** |
| 첫 화면에 필요한 `sm3-latin` | **10.7 KB** |

모눈에 적히는 건 숫자뿐이라 첫 화면은 라틴 조각 하나로 끝난다. 한글 조각은
방명록에 그 글자가 올라올 때만 뒤늦게 받아진다.

```bash
npm run font
```

> 상용 폰트다. 공개 URL 에 올리면 서브셋 파일이 그대로 배포된다.
> 웹폰트 사용 범위가 라이선스에 포함되는지는 확인이 필요하다.

## 배경 텍스처

맨 뒤에 영상이 전체화면으로 아주 옅게 깔린다.

`mix-blend-mode: multiply` 로 합성해서 **어두운 부분만 남는다** — 흰 종이에
옅게 인쇄된 것처럼 보이고 화면이 빛나 보이지 않는다. 흑백으로 빼고 불투명도는
`0.14`. 영상이 없거나 자동재생이 막혀도 흰 바탕 그대로라 화면이 깨지지 않는다.

진하기는 [`src/style.css`](src/style.css) 의 `.bg { opacity }` 한 줄이다.

### 인코딩

`ACT_video_1` (30.6초) 과 `ACT_video_2_1` (59.6초) **두 편을 한 파일로 이어붙인다.**
그러면 `loop` 속성만으로 A → B → A → B 가 되고, 재생 중에 파일을 갈아끼우느라
생기는 끊김이 없다. 두 편 사이에는 1초 크로스페이드를 넣었다.

**흑백을 파일에 구워 넣었다.** 어차피 화면에서 흑백으로 쓰는데, 색 정보를
남겨두면 용량만 먹고 브라우저가 매 프레임 `grayscale()` 필터를 돌려야 한다.
하루 종일 켜두는 화면이라 그만큼 아낀다.

| | |
| --- | --- |
| 원본 두 편 | 236 MB (둘 다 1080p30 · 21 Mbps) |
| 720p24 · CRF 33 · 흑백 · 무음 | **3.97 MB** (89.2초 · 356 kb/s) |

원본은 `.gitignore` 로 제외되고 `public/bg.mp4` 만 배포된다. 다시 뽑으려면:

```bash
npm run bg -- 앞영상.mp4 뒤영상.mp4
# 앞영상 길이가 30.6초가 아니면 전환 지점을 같이 준다 (길이 - 1)
npm run bg --offset=44.5 -- 앞영상.mp4 뒤영상.mp4
```

> 되감았다 도는 지점(B 끝 → A 처음)은 컷이다. 90초에 한 번,
> 그것도 불투명도 14% 라 눈에 잘 안 띈다. 거슬리면 말해달라 —
> 정방향 뒤에 역방향을 붙여 이음매를 없앨 수 있다 (용량은 두 배).

## 형태를 만드는 규칙 — [`src/grid.ts`](src/grid.ts)

한 줄마다 척추 위치를 정하고, 좌우로 한 칸씩 나가면서 살아남을지 뽑는다.
칸에 적히는 숫자가 곧 척추로부터의 거리다.

```
survival(d)  거리에 따른 생존 확률. exp(-d/18)
region       큰 구조. 낮은 곳은 통째로 비워 가지 사이 여백을 만든다
mid          가로로 늘인 결. 남은 곳을 줄무늬로 뭉친다
runR         가로 4칸이 같은 값을 공유 → 낱알이 아니라 2~6칸 토막으로 남는다
cellR        그 토막 안에 다시 구멍을 낸다
```

`runR` 이 핵심이다. 칸마다 독립적인 난수만 쓰면 고르게 흩뿌린 점이 되어버린다.
가로로 값을 공유시켜야 레퍼런스처럼 **짧은 토막**이 나온다.

`reach()` 의 포락선은 위쪽 절반을 넓게 유지하다가 아래로 가며 줄기만 남긴다.
`pow(1-t)` 를 쓰면 맨 위에서만 넓고 곧장 좁아져 레퍼런스와 어긋난다.

전부 결정론적이라 같은 화면 크기면 언제나 같은 그림이 나온다.

### 손질할 만한 값

| 값 | 하는 일 |
| --- | --- |
| `CELL_TARGET` | 한 칸 크기 (24px) |
| `survival()` 의 `18` | 클수록 멀리까지 흩뿌려진다 |
| `reach()` 의 `62` / `24` | 좌 / 우로 뻗는 최대 거리 |
| `cellR > 0.86` | 토막 안 구멍의 양 |
| `TONE_MIN` / `TONE_MAX` | **채워진 칸의 회색 범위** |
| `BREATH` | 한 번 숨쉬는 데 걸리는 시간 (6.5초) |
| `buildCells` 끝의 시드 `907` | 칸이 채워지는 순서(무작위 배치) |

`buildCells(cols, rows)` 는 캔버스와 무관한 순수 함수다. 형태를 손볼 때는
따로 떼어 ASCII 로 뽑아 확인할 수 있다.

## 참고

- 욕설·스팸에 걸린 줄은 지우지 않고 조용히 격리한다. 작성자 화면에는
  등록된 것처럼 보이고 판면에만 안 뜬다.
  금칙어는 [`src/filter.ts`](src/filter.ts) 의 `WORDS` 에 있다.
- 브라우저 데이터를 지우면 기록도 사라진다. 콘솔에서 `store.toJSON()` 으로
  꺼내둘 수 있다.
- 기록은 "그 브라우저의 그 주소"에 묶인다. `localhost` 로 쓰다가 Vercel URL
  로 바꾸면 이전 기록이 안 보인다 — 처음부터 한쪽으로 정할 것.
- 칸 수가 곧 수용량이다. 1920×1080 기준 약 900~1200칸.
  다 차면 더 이상 입력되지 않는다.
