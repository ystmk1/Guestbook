# Sympoiesis

ACT 2026 전시 방명록.

모눈 종이 한 장. 가운데를 흐르는 척추(`0`)에서 좌우로 멀어질수록 숫자가 커지고,
멀수록 칸이 성기게 흩어져 손그림 등고선처럼 보인다.

**방명록 한 줄 = 칸 하나.** 위에서부터 한 칸씩 차오른다.
채워진 칸을 누르면 그 줄이 나온다.

---

## 실행

```bash
npm install
npm run dev
npm run build
```

기록은 이 브라우저의 `localStorage` 에 저장된다. 인터넷 없이 동작한다.

캔버스에 캐시해두고, 매 갱신마다 통째로 복사한 뒤 채워진 칸만 그 위에 얹는다.
칸이 수천 개여도 다시 그릴 일이 없고, 애니메이션이 도는 순간(새 칸이 스며드는
0.5초)을 빼면 `requestAnimationFrame` 루프 자체가 돌지 않는다.

## 형태를 만드는 규칙 — [`src/grid.ts`](src/grid.ts)

한 줄마다 척추 위치를 정하고, 좌우로 한 칸씩 나가면서 살아남을지 뽑는다.
칸에 적히는 숫자가 곧 척추로부터의 거리다.

```
survival(d)  거리에 따른 생존 확률. exp(-d/18)
region       큰 구조. 낮은 곳은 통째로 비워 가지 사이 여백을 만든다
mid          가로로 늘인 결. 남은 곳을 줄무늬로 뭉친다
runR         가로 4칸이 같은 값을 공유 → 낱알이 아니라 2~6칸 토막으로 남는다
cellR        그 토막 안에 다시 구멍을 낸다
```

`runR` 이 핵심이다. 칸마다 독립적인 난수만 쓰면 고르게 흩뿌린 점이 되어버린다.
가로로 값을 공유시켜야 레퍼런스처럼 **짧은 토막**이 나온다.

`reach()` 의 포락선은 위쪽 절반을 넓게 유지하다가 아래로 가며 줄기만 남긴다.
`pow(1-t)` 를 쓰면 맨 위에서만 넓고 곧장 좁아져 레퍼런스와 어긋난다.

전부 결정론적이라 같은 화면 크기면 언제나 같은 그림이 나온다.

### 손질할 만한 값

| 값 | 하는 일 |
| --- | --- |
| `CELL_TARGET` | 한 칸 크기 (24px) |
| `survival()` 의 `18` | 클수록 멀리까지 흩뿌려진다 |
| `reach()` 의 `62` / `24` | 좌 / 우로 뻗는 최대 거리 |
| `cellR > 0.86` | 토막 안 구멍의 양 |
| `FILL` | **채워진 칸 색** |

`buildCells(cols, rows)` 는 캔버스와 무관한 순수 함수다. 형태를 손볼 때는
따로 떼어 ASCII 로 뽑아 확인할 수 있다.

## 참고

- 욕설·스팸에 걸린 줄은 지우지 않고 조용히 격리한다. 작성자 화면에는
  등록된 것처럼 보이고 판면에만 안 뜬다.
  금칙어는 [`src/filter.ts`](src/filter.ts) 의 `WORDS` 에 있다.
- 브라우저 데이터를 지우면 기록도 사라진다. 콘솔에서 `store.toJSON()` 으로
  꺼내둘 수 있다.
- 기록은 "그 브라우저의 그 주소"에 묶인다. `localhost` 로 쓰다가 Vercel URL
  로 바꾸면 이전 기록이 안 보인다 — 처음부터 한쪽으로 정할 것.
- 칸 수가 곧 수용량이다. 1920×1080 기준 약 900~1200칸.
  다 차면 더 이상 입력되지 않는다.
